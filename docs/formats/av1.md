# AV1 and AVIF

Decoder in `crates/oc-av1`, written from the AV1 Bitstream & Decoding Process Specification (`docs/specs/av1-spec.pdf`) with no other decoder consulted. Decoding only: AV1 is a read-only video input (MP4, WebM, Matroska, raw `.obu`) and AVIF a read-only picture input.

**Decoder.** Every part of the decoding process in the specification, for operating point 0: sequence and frame headers, all block syntax and the symbol decoder, intra prediction (directional with edge filter and upsampling, smooth, Paeth, filter-intra, palette, chroma-from-luma, intra block copy), inter prediction (scaled references, OBMC, local and global warp, wedge, difference-weighted and distance-weighted compound, inter-intra), motion-vector prediction and the motion field projection, all inverse transforms including the identity and 64-point ones, quantiser matrices, segmentation, delta q and delta lf, the deblocking filter, CDEF, super-resolution, loop restoration (Wiener and self-guided), film grain synthesis, tiles, `show_existing_frame`, and 8, 10 and 12 bit in 4:0:0, 4:2:0, 4:2:2 and 4:4:4. The default CDFs and the other tables are generated from the specification text by `tools/av1_spec_text.py`, `tools/gen_av1_tables.py` and `tools/gen_av1_cdf.py`, so none was copied from another decoder.

**How it was checked.** `crates/oc-av1/tests/data` holds streams encoded by libaom and SVT-AV1 (through ffmpeg) and the frames dav1d decodes from them; `tests/dav1d.rs` requires an exact match: lossless 4:2:0 and 4:4:4 (isolating syntax and prediction), lossy with CDEF and loop restoration, 10-bit, film grain, monochrome and a hierarchical SVT-AV1 stream. During development the same comparison was run on a few hundred more streams (libaom, SVT-AV1 and rav1e; tiles; odd sizes; 8, 10 and 12 bit; 4:4:4; every film-grain test vector libaom offers). The damage test flips bits and truncates the fixtures and requires errors, never panics.

**Video.** `oc_video::av1` feeds each packet to the decoder, after the sequence header held in the `av1C` box, and keeps the last picture shown. As for the other codecs, higher bit depths are rounded to 8 bit and 4:2:2 and 4:4:4 chroma is averaged to 4:2:0.

**AVIF.** `oc_image::avif` reads the HEIF item structure: the primary `av01` item or a `grid` of them, an auxiliary alpha image, `colr` (`nclx` for the matrix and range, `prof` for an ICC profile) and the `clap`, `irot` and `imir` properties. Chroma is upsampled bilinearly. Output is 8 bit, or 16 bit when the image has more than 8. A file whose matrix coefficients are unspecified is read as BT.601, which is what ffmpeg and libavif's default do. Animated (`avis`) files give their primary still image.

**Not done.** AV1 or AVIF encoding; large-scale tile decoding; spatial and temporal scalability beyond choosing operating point 0; the super-resolution path is written from the specification but no stream in the test set uses it (libaom's command-line encoder is the only one that can produce it); AVIF `imir` follows the HEIF second edition (axis 0 is a left-right mirror), which no fixture exercises; grid and transform properties are untested for the same reason.
