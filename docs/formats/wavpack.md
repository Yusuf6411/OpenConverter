# WavPack

Decoder in `crates/oc-audio/src/wavpack.rs`, read only: there is no WavPack encoder, so `.wv` is an input format (to WAV, FLAC, Opus and the rest).

**Decoder.** Lossless and hybrid-lossy blocks, mono, stereo (joint and independent), false stereo, multichannel files (blocks of a sequence joined into frames, with the channel mask), 8 to 32 bit integers including the extension stream that carries bits beyond 24 and shifted or factored samples, non-standard sample rates, and the block checksums (a block that fails its checksum is an error, not noise). The file layout is from the format document in `docs/specs/WavPack5FileFormat.pdf`. The entropy coder and the decorrelation passes follow the reference decoder, because the format document does not describe them; the two logarithm tables are generated by formula and were checked equal to the reference's tables.

No source text was copied; the structure of the algorithm is.

**How it was checked.** `tools/make_wavpack_fixtures.py` encodes 14 files with ffmpeg's WavPack encoder (8, 16, 24 and 32 bit; mono, stereo, 3, 6 and 8 channels; four compression levels; joint stereo on and off; 37.8 kHz; a 17 sample file) from signals with silence and very quiet passages, so that the zero-run code is used. `crates/oc-audio/tests/wavpack.rs` requires the decoded samples to hash the same as ffmpeg's decoder output. Damaged and truncated copies must fail with errors, never panic. Fuzz target `wavpack`.

**Not tested.** Hybrid (lossy) blocks decode through the same paths as the reference, but no encoder available here produces them, so that code has not been exercised by a real file. The same holds for the old 4.0 stream version (refused) and for files with an `ID_WVX` stream written by the original encoder (ffmpeg's 32-bit files do pass).

**Not done.** WavPack writing; floating-point blocks (refused with a clear error); DSD blocks; correction files (`.wvc`), which make a hybrid file lossless; MD5 verification.
