# JPEG XL

Decoder in `crates/oc-jxl`, wired into the image formats by `crates/oc-image/src/jxl.rs`. It is read only: `.jxl` is an input format (to PNG, JPEG, WebP and the rest); there is no JPEG XL encoder. Only the first displayed frame of an animation is decoded; the conversion carries a note saying so.

**What is decoded.** Bare codestreams and the ISO BMFF container (`jxlc` and split `jxlp` boxes; other boxes are skipped, so Exif and XMP are not carried over, and a `jbrd` box is ignored: the pixels of a recompressed JPEG are decoded, the original JPEG bytes are not rebuilt).

- Modular frames: all predictors including the weighted predictor, meta-adaptive trees, RCT, palette (including delta palettes) and squeeze transforms, any group size, extra channels.
- VarDCT frames: every transform type (DCT from 8x8 to 256x256, rectangular, 4x4, 8x4, 4x8, Hornuss, AFV, DCT2x2), default and custom quantisation tables, chroma from luma, adaptive LF smoothing, the Gaborish and edge preserving filters, multiple passes (progressive AC), progressive DC frames (LF frames at any level), group ordering.
- JPEG recompression: YCbCr frames with 4:4:4, 4:2:2, 4:4:0 and 4:2:0 chroma subsampling, grey. The chroma planes are upsampled with the triangle filter the format specifies.
- Frame features: patches, 2x, 4x and 8x upsampling of colour and extra channels (default and custom kernels), noise synthesis, reference slots, frame blending (replace, add, multiply, alpha blend, multiply-add), cropped frames, save-before-colour-transform frames.
- Samples: 1 to 16 bit integers, 16 and 32 bit floats (clamped to 0..1 on output), grey, RGB, alpha (straight and premultiplied; the output is straight), orientation.
- Colour: XYB to sRGB; files in other RGB or grey spaces (primaries and transfer function given by the header) are converted to sRGB with a Bradford adaptation. Files with an embedded ICC profile that were stored without XYB keep their samples in the profile's space and the profile travels in the image metadata, where the engine's colour management converts it (or keeps it) like any other ICC profile. The compact form of the profile is rebuilt byte for byte.

**Not done.** Splines (refused with a clear error; no encoder available here writes them, so the code could not be checked); HDR transfer functions are mapped to sRGB without tone mapping, with a note; extra channels other than alpha are dropped with a note; progressive previews of a truncated file; modular YCbCr frames; layered animation output; the container's Exif and XMP.

**How it was checked.** The oracle is libjxl 0.11.1 (`cjxl` and `djxl`, from the project's release archive) and libjxl 0.12 through Python's `imagecodecs`. Lossless files (every effort, predictor, group size, palette, squeeze, 8 and 16 bit, alpha, grey) match libjxl bit for bit. Lossy files (efforts 1 to 10, distances 0.3 to 8, grey, alpha, 16 bit, float, multi-group images, resampling 2, 4 and 8, extra channel resampling, photon noise, progressive AC, progressive DC with one and two LF levels, patches, EXIF orientations, non-sRGB colour spaces, an ICC profile that libjxl converted to custom primaries) differ from libjxl by at most one level in 8 bit and a few in 16 bit, which is the rounding of the float pipeline. JPEG recompressions of the repository's JPEG fixtures (4:4:4, 4:2:2, 4:2:0, grey, odd sizes down to 1x1, restart intervals) match libjxl within one level. `crates/oc-image/tests/jxl.rs` keeps 40 of these files with libjxl's decoded pixels, checks that the ICC profile is rebuilt exactly, and damages every file; an ignored test runs tens of thousands of mutations (`cargo test -p oc-image --test jxl --release -- --ignored`). Fuzz target `jxl`.

**Colour check that libjxl cannot give.** For lossless files in a non-sRGB space `djxl` returns the stored numbers unconverted, so those files were checked by computing the transfer function by hand instead; the lossy path (which `djxl` does convert) agrees with the same code.

**Credit.** The format follows ISO/IEC 18181-1. Where the text leaves a detail open (the order of the LF global fields, the size rounding of subsampled channels, the noise generator's layout, the default upsampling kernels, the structure of the compact ICC encoding) the code was compared with `jxl-oxide` (Copyright (c) the jxl-oxide authors, MIT or Apache-2.0), whose structure it follows in those places. No `jxl-oxide` source was copied beyond the specification's constant tables (upsampling kernels). The code is otherwise written for OpenConverter.
