# Translations

The web interface and the desktop app share `ui/`. Text lives in the page (English) and in catalogs `ui/locales/<lang>.json`, flat `key: text` files; `{name}` marks a value filled in at run time.

- English is `en.json`, generated from `ui/index.html` by `python3 tools/i18n.py extract` (elements carry `data-i18n="key"`).
- `qps.json` is the pseudo-locale: accented, padded text in brackets. Open `/?lang=qps` to see which strings are still hard-coded (they stay plain) and where longer text breaks the layout. Regenerate with `python3 tools/i18n.py pseudo`.
- `python3 tools/i18n.py check` and the `translation_catalogs_match_the_page` test keep catalogs and page in step.
- The language comes from `?lang=`, the saved `oc-lang` value, then the browser language; a missing catalog or key falls back to English.

To add a language: copy `en.json` to `<lang>.json`, translate the values, run `check`.

Not done: strings that JavaScript builds (card status, errors, dialogs) are not in the catalog yet and `t()` is used only for theme names; there is no language picker in Settings; no real translation has been contributed.
